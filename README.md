# PocketCard

Нативное iPhone-приложение: персональные карточки с фотографией и/или текстом, локальная коллекция и выпуск подписанных карточек Apple Wallet.

**Проверено на Mac · 27 сентября 2026.** Приложение собрано в Xcode 26.6 и запущено на iPhone 16 Pro Simulator (iOS 18.5). Проверены импорт фото, сохранение карточки, сохранность после перезапуска и предпросмотр. Прошли 23 теста Swift-ядра, 52 теста сервиса, 4 структурные проверки и 7 нативных XCTest. Один тест защиты файлов явно пропускается в Simulator и требует физического iPhone. Выпуск настоящего Apple Wallet pass и готовность к App Store пока не подтверждены. Подробности: [docs/VERIFICATION-MAC.md](docs/VERIFICATION-MAC.md).

## Начать с приложения

На Mac с Xcode 16+ откройте **`ios/PocketCard.xcodeproj`**, выберите схему **PocketCard** и iPhone Simulator с iOS 17+, нажмите **Run**. Генератор проекта, CocoaPods, XcodeGen и внешние iOS-библиотеки не требуются. Swift Package `PocketCardCore` подключён из корня этого же репозитория.

По умолчанию включён локальный режим: создание, просмотр, копирование, редактирование и удаление карточек, кадрирование и предпросмотр. Сервис и аккаунт Apple не нужны для этих действий. Выпуск в Wallet станет доступен после настройки собственной идентичности Apple и HTTPS-сервиса — [пошаговая инструкция](docs/SETUP.md).

## Что реализовано

- Три готовые композиции: **Фото**, **Информация**, **Фото + информация**. Четыре темы.
- Произвольные текстовые поля; значения остаются строками, включая ведущие нули. Локальные незаполненные черновики разрешены.
- Системный выбор фотографии или импорт из Файлов. Кадр, масштаб и положение; уменьшенная рабочая копия без исходных метаданных.
- Коллекция с отдельной карточкой, полным текстом и фотографией. Смена шаблона сохраняет скрытые исходные данные локально, но не экспортирует их.
- Защищённые средствами iOS атомарные записи в Application Support. Изоляция повреждённых записей, контроль устаревшего редактирования, сохранность изображения у копий.
- Разные ориентировочные предпросмотры PocketCard, классического Generic и Poster Generic. Фотопакет содержит `posterGeneric` и `generic` fallback; реальное отображение iOS 27+ нужно проверить на устройстве.
- Явное подтверждение передачи содержимого оператору. HTTPS-клиент запрещает перенаправления, ограничивает размер ответа, проверяет ID/версию/контрольную сумму и вызывает системный экран Wallet. Ручное обновление уже добавленной карточки.
- Статус Wallet определяется по доступной библиотеке, а не фактом закрытия окна. Удаление из приложения **не удаляет** отдельную копию Wallet.
- Приватный сервис FastAPI: токен установки, строгая схема, ограничение нагрузки, подготовка PNG, manifest и настоящая detached CMS-подпись. Нет поддельного «успешного выпуска», когда сертификат отсутствует.

## Проверки

```bash
# Из корня проекта. Python 3.12+; в этой поставке проверен Python 3.13.
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e './signer[test]'
bash scripts/test-all.sh
```

На Mac скрипт также запускает нативные тесты в установленном iPhone Simulator. На Linux честно сообщает об их пропуске. Отдельно:

```bash
swift test
(cd signer && python -m pytest -q)
python scripts/check_wire_contract.py
python -m unittest discover -s scripts/tests -v
bash scripts/test-ios.sh  # Только Mac/Xcode
```

## Репозиторий и локальная конфигурация

Исходники подготовлены для https://github.com/abuzo/pocketcard-ios, ветка `feature/initial-import`. Токены, закрытые ключи, сертификаты Apple и пользовательские карточки в Git не включаются. **Не добавляйте** `.env`, `ios/Local.xcconfig`, сертификаты, ключи и выпущенные `.pkpass`. Шаблоны `.env.example` и `ios/Local.xcconfig.example` безопасны для коммита. Не потеряйте скрытые `.github` и `.gitignore` при копировании.

## Ограничения, которые важно знать

PocketCard **не является менеджером паролей**. `.pkpass` подписан, но не зашифрован; сервер выпуска видит отправленное содержимое. Локальная защита файлов iOS не равна отдельной блокировке Face ID. Системные резервные копии могут включать файлы приложения. В первой версии нет синхронизации iCloud, аккаунтов, подписок, совместного доступа и автоматических push-обновлений Wallet.

Сервис рассчитан на **личную установку с одним токеном**, а не на публичный многопользовательский SaaS. Для публикации нужны дополнительная модель авторизации, проверка развёртывания и зависимостей, политика конфиденциальности и проверка назначения Wallet-карточек по правилам Apple. Наличие исходников не гарантирует одобрение App Store.
