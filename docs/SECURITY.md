# Границы безопасности PocketCard MVP

## Где находятся данные

Приложение получает приватный путь через `FileManager.applicationSupportDirectory`. Структура внутри контейнера:

```text
Library/Application Support/PocketCard/cards/<UUID>.json
Library/Application Support/PocketCard/images/<UUID>.jpg
```

Физический UUID контейнера выдаёт iOS; он не зашит в код. JSON и рабочие фотографии записываются атомарно с `completeFileProtection`, каталоги получают соответствующую защиту. JSON остаётся обычным JSON после разблокировки устройства; собственной криптографической базы и отдельного запроса Face ID в MVP нет. Пользовательский пароль не распознаётся по названию поля и не превращается автоматически в запись Keychain.

Сервисные настройки и токен хранятся в Keychain с `WhenUnlockedThisDeviceOnly`, без синхронизации. Рабочая фотография уменьшается до 2048 пикселей, оригинал в приложении «Фото» не изменяется. Кадрирование не разрушает уменьшенную рабочую копию.

Приложение не настраивает iCloud-синхронизацию, но файлы могут попасть в системную резервную копию устройства. Удаление приложения обычно удаляет его файловый контейнер; Keychain может пережить переустановку, поэтому для удаления настройки существует отдельная кнопка. Копия Wallet живёт независимо.

## Граница передачи

Никакой сетевой передачи при открытии, редактировании или сохранении карточки. После явного подтверждения отправляются только данные выбранного шаблона: подготовленное фото без исходных EXIF/GPS, нужный текст, ID/версия/тема и контрольная сумма. Скрытые поля/фото исключены. Имя оператора вводится владельцем установки, а не подтверждается сервисом третьей стороны.

Клиент принимает только HTTPS origin без логина, query и fragment. Он не следует редиректам и не отключает системную проверку TLS. Для запроса используется ephemeral URLSession без дискового кэша и cookies. Подготовленный pass остаётся в оперативной памяти до передачи Wallet; отдельный локальный архив `.pkpass` приложение не сохраняет.

Сервер видит содержимое в памяти: это **не сквозное шифрование от сервера**. TLS защищает транспорт, CMS защищает целостность пакета, SHA-256 связывает ответ с запросом; ни один из этих механизмов не делает поля Wallet секретными от владельца файла.

## Сервис подписи

Вход ограничен 5 MiB, точная строка metadata — 64 KiB. Сервер запрещает неизвестные ключи, дубли ключей JSON, некорректный Unicode, лишние данные скрытого шаблона, некорректные UUID и несоответствие хеша. Графика принимается только как ограниченный JPEG/PNG и повторно растрируется; произвольные ZIP, URL, пути файлов и готовые pass.json от клиента не принимаются.

Bearer-токен сравнивается до разбора содержимого; один выпуск одновременно, 10 авторизованных попыток за минуту, ограничение чтения тела 15 секунд. Это лимиты **одного процесса и одной установки**, не полноценная защита публичной платформы от DoS. Скрипт запускает одного worker; количество workers без изменения модели лимитов увеличивать нельзя.

Проверяются соответствие приватного ключа сертификату, Pass Type ID в UID, Team ID в OU, подписи цепочки до настроенного корня и срок действия. Настроенный корень — доверенная конфигурация оператора: программа не доказывает, что произвольный переданный корень принадлежит Apple. OCSP/CRL и онлайн-отзыв сертификатов здесь не реализованы. Проверяйте актуальность сертификатов перед развёртыванием и обновляйте их своевременно.

Manifest использует требуемый форматом SHA-1; detached CMS-подпись — SHA-256, включает промежуточный сертификат. Тестовая PKI создаётся во временных каталогах: такие пакеты доказывают криптографическую корректность реализации, но **не принимаются как Apple-valid Wallet passes**.

Сервис не пишет тела запросов и фото в БД/файлы и не включает значения в сообщения ошибок. Это не гарантия физического стирания Python-памяти, отсутствие swap/core dump или правил внешнего прокси. Оператор обязан отключить дампы и сбор request bodies, ограничить доступ к процессу/секретам и проверить политику hosting/APM.

## Проверка ответа и статуса

Приложение сравнивает serialNumber, Pass Type ID, версию, ID и hash с подтверждённым запросом. Заявленный Team ID находится в подписанном `userInfo`; это не отдельный валидатор Apple PKI в клиенте. Окончательную пригодность и подпись pass проверяет системный Wallet.

После сетевого ответа повторно проверяется, что исходная карточка не удалена и не изменена. «Выпущено» не равно «добавлено». Источник статуса — доступная приложению библиотека Wallet и фактическая версия. Удаление локальной карточки не удаляет её Wallet-копию.

В app switcher предусмотрен нейтральный экран поверх окна, включая sheets. Это требует ручной проверки на устройстве и не запрещает обычные скриншоты, запись экрана, доступ на разблокированном устройстве или извлечение pass. `sharingProhibited` скрывает стандартную кнопку распространения, а не шифрует файл.

## Перед публичным запуском

Нужны независимый security review, контроль обновлений/уязвимостей зависимостей, модель авторизации отдельных пользователей и квот, управление сроками токенов, проверка TLS/логирования/резервных копий, реальные тесты устройств, политика конфиденциальности и проверка правил Apple. Импорт случайного сертификата, обход проверки TLS и общий встроенный в приложение токен — не решение этих задач.

Не используйте MVP для банковских секретов, seed-фраз, паролей Apple Account или кодов восстановления. Наличие текста предупреждения не делает такую эксплуатацию безопасной.
