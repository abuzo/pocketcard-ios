# Проверка поставки — 27 сентября 2026

## Итог

**Исходники основных компонентов MVP написаны и включены в архив. Переносимые проверки проходят. Нативная сборка iOS и приём pass настоящим Wallet не проверены.** Это исходный проект для запуска и приёмки на Mac, не готовая подписанная программа и не подтверждение App Store readiness.

Среда проверки: Linux x86_64, Swift 6.2.1, Python 3.13.5, OpenSSL 3.5.5. Xcode и Apple SDK в этой среде отсутствуют. Никакие пользовательские данные, реальные Apple signing keys и рабочий токен не использовались.

В начале работы исходные 17 Swift-тестов проходили. Для новых переносимых политик и ошибки предельной версии наблюдались RED → GREEN. Сервисные тесты написаны до реализации. Дополнительные приёмочные тесты конкурентного выпуска и межъязыкового контракта проверяют уже реализованный код.

Сервисные тесты проверяют границы запросов, аутентификацию, фильтрацию скрытых данных, Unicode, типы, повреждённые запросы, графику, manifest, проверку CMS через OpenSSL, подмену manifest, ошибки/истечение сертификата, rate limit и один выпуск одновременно. Временная тестовая цепочка не является Apple PKI; криптографическая проверка не означает приём пакета Wallet.

## Проверка кода и исправления

Проведён собственный проход по интерфейсам, приватности, обработке ошибок и комплектности. Независимый reviewer/внешний security audit **не проводился**. Исправлены сохранение предельной версии с защитой прежней записи, присутствие заявленного Team ID в userInfo, устаревающая загрузка фото редактора, ключ перерисовки при смене шаблона и предупреждение при полностью нечитаемой коллекции. Для предельной версии добавлен воспроизводящий тест.

## Что ещё не проверено

- **Компиляция и запуск SwiftUI/PassKit на Apple SDK.** Linux parser не замечает неверную сигнатуру SDK, actor-isolation mismatch, проблему linker/signing или ошибку type inference. Поэтому требуется `bash scripts/test-ios.sh` на Mac и фактический Run приложения.
- **8 нативных XCTest** (ImagePipeline, PreparedIssue, iOS protection attributes) написаны, но не запускались. Они не входят в 79 проходящих переносимых тестов.
- Реальная выдача и установка `.pkpass` с сертификатом Apple; отображение Poster Generic на iOS 27+ и классического fallback на старых версиях.
- Provisioning/entitlement на настоящем iPhone; уведомления Wallet, обновление версии и удаление вне приложения.
- Поведение VoiceOver/Dynamic Type, фотографий iCloud, ошибок доступа к фото, memory pressure, блокировки устройства и app-switcher cover.
- CI на GitHub, сетевое развёртывание/доверенный TLS, конкретная инфраструктура логирования, vulnerability scan зависимостей, App Review.

## Приёмка на устройстве

1. Запустить `scripts/test-ios.sh`, затем открыть схему PocketCard и выполнить Run. Не считать проект готовым к распространению при ошибках этой проверки.
2. Создать все три шаблона; проверить пустые черновики и обязательные данные для выпуска. Закрыть и вновь открыть приложение.
3. Ввести `0001`, кириллицу, emoji, длинное значение; проверить пределы и полноту подробностей.
4. Выбрать фото из Photos и Files, изменить кадр и тему, сменить шаблон туда/обратно: локальные данные остаются, скрытые отсутствуют в передаче.
5. Создать копию фотокарточки, удалить оригинал: фото копии остаётся. Изменить карточку и проверить увеличение версии.
6. Выпустить синтетическую карточку через свой HTTPS-сервис. Отменить системное добавление: статус «В Wallet» не появляется. Добавить повторно и проверить реальную библиотеку.
7. Отредактировать установленную карточку: статус «Есть изменения», ручное обновление заменяет её, а не создаёт дубликат.
8. Удалить pass в Wallet, вернуться в приложение; удалить карточку в PocketCard — pass в Wallet при этом остаётся.
9. Проверить неверный токен/недоступную сеть/отключённый сервис: локальная карточка остаётся, показана объяснимая ошибка, фальшивого успеха нет.
10. Проверить app switcher с открытыми редактором, настройками и предпросмотром; блокировку/разблокировку; обычные скриншоты не должны считаться запрещёнными.
