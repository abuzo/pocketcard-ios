# PocketCard MVP Implementation Plan

> **For agentic workers:** use superpowers:executing-plans to implement and verify this plan task by task.

**Goal:** Implement the agreed native iPhone editor, protected local persistence and a private Wallet signing service.

**Architecture:** A portable Swift package owns the data model, validation, projection and atomic repository. SwiftUI handles photos, UI and PassKit. A separate FastAPI service validates a small structured request and signs a package in memory.

**Tech Stack:** Swift 6 compiler in Swift 5 compatibility mode; iOS 17+; SwiftUI, PhotosUI, ImageIO, CryptoKit, Security, PassKit. Python 3.12+; FastAPI, Pydantic, Pillow and cryptography.

**Spec:** ../specs/2026-09-27-pocketcard-design.md

## Global constraints

- Three templates; hidden fields/photos/caption never exported by another template.
- 60 Unicode scalars for title, 500 caption, 10 fields, 40 label, 2000 value. Visible value >80 scalars becomes “См. подробности”.
- Draft saving works without credentials or a server. No secret values on library rows.
- Import <=25 MiB and <=50 million pixels before full decode. Export is a metadata-free rendered image, not the original.
- Metadata <=64 KiB; request <=5 MiB. JSON envelope holds the exact metadata string, imageBase64, and SHA-256(metadata UTF-8 + zero byte + decoded image).
- Server owns pass type/team/issuer. TLS and explicit consent required. Installation token is in Keychain, not compiled into the app.
- .pkpass is signed, not encrypted. No third-party analytics and no request/body logging.
- Photo passes use artwork.png with posterGeneric and a classic generic fallback. Device validation remains required.
- Do not replace or bypass GitHub authorization. A 403 from contents API means no remote write; deliver a source archive with the actual status.

## Review focus

1. Template switches retain local originals but do not leak hidden data: projection tests.
2. An old network response or a cancelled Wallet sheet must never mark a new revision installed: status tests and physical-device checklist.
3. Corrupt files and failed writes preserve other cards and the previous version: repository tests.
4. Huge images, invalid UTF-8, duplicate JSON keys and duplicate field IDs fail safely: API tests.
5. A mismatched/expired certificate or anonymous request must never issue a pass: signing and API tests.
