# Запуск PocketCard на Mac

## 1. Открыть приложение без сервера

Распакуйте архив целиком: `Package.swift` должен находиться рядом с папками `ios` и `signer`. В Xcode 16 или новее откройте `ios/PocketCard.xcodeproj` и выберите схему **PocketCard**. Выберите установленный **iPhone Simulator с iOS 17+** и нажмите Run. Внешних Swift-зависимостей нет.

Создайте по карточке каждого вида. В локальном режиме должны работать сохранение черновика, перезапуск, фото, поля, смена шаблона, копирование и удаление. Кнопка выпуска объясняет, что Wallet пока не настроен; локальная работа от этого не зависит.

Для запуска на своём iPhone без Wallet выберите свою Signing Team в Xcode и уникальный Bundle Identifier. Не включайте Wallet до настройки соответствующего Pass Type ID. Для iPhone с системой новее установленного Xcode потребуется поддерживающая её версия Xcode.

## 2. Идентичность Wallet

Потребуются собственные Team ID, Pass Type ID и действующий **Pass Type ID Certificate** Apple с соответствующим закрытым ключом. Сертификат подписи приложения и сертификат выпуска `.pkpass` — разные вещи. Доступ к нужным сертификатам определяется членством Apple Developer.

Создайте Pass Type ID в Apple Developer → Certificates, Identifiers & Profiles → Identifiers, например `pass.com.yourcompany.pocketcard`. Выпустите сертификат для этого идентификатора по CSR.

Один из способов создать CSR на Mac — локально, в каталоге вне репозитория:

```bash
mkdir -p "$HOME/.pocketcard-secrets"
chmod 700 "$HOME/.pocketcard-secrets"
cd "$HOME/.pocketcard-secrets"
openssl genrsa -aes256 -out pass-key.pem 2048
openssl req -new -key pass-key.pem -out pass.csr -subj "/CN=PocketCard/"
chmod 600 pass-key.pem
```

Команды запросят пароль ключа. Не отправляйте ключ или пароль в чат. Загрузите **только CSR** в портал Apple; скачанный pass-сертификат сохраните рядом с ключом. Получите соответствующий промежуточный WWDR-сертификат и его корневой Apple CA из официального Apple PKI. Выбирайте цепочку, которая действительно подписала ваш pass-сертификат, а не случайный WWDR из старой статьи. Сервис проверяет цепочку и совпадение ключа; вы отвечаете за то, что заданный корень взят у Apple.

В корне проекта:

```bash
cp ios/Local.xcconfig.example ios/Local.xcconfig
```

Заполните свой `POCKETCARD_BUNDLE_ID`, десятисимвольный `DEVELOPMENT_TEAM` и `WALLET_PASS_TYPE_ID`. Для выпуска установите `WALLET_ACCESS_ENABLED = YES` и оставьте `PC_APP_ENTITLEMENTS = PocketCard/PocketCard.entitlements`.

В App ID/provisioning profile приложения должен быть разрешён Wallet. Файл entitlements запрашивает только `$(TeamIdentifierPrefix)$(WALLET_PASS_TYPE_ID)`, а не произвольные карточки пользователя. Проверьте Signing & Capabilities в Xcode; Xcode может запросить обновление профиля. Перед запуском на iPhone дождитесь устранения ошибок подписи.

**Идентификаторы в сборке, в сервисе и в сертификате должны совпадать.** Самостоятельно придуманное значение Team ID не заменяет реальный Apple Team ID.

## 3. Поднять приватный сервис

Из корня проекта, используя Python 3.12+ (проверено на 3.13):

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -e './signer[test]'
cp .env.example .env
chmod 600 .env
python -c 'import secrets; print(secrets.token_urlsafe(48))'
```

Последняя команда выводит **ваш новый секретный токен**. Вставьте его в `PC_TOKEN` своего `.env`; не коммитьте этот файл и не вставляйте токен в команды curl или скриншоты. Заполните остальные поля:

| Переменная | Значение |
|---|---|
| `PC_PASS_TYPE_ID`, `PC_TEAM_ID` | Та же идентичность, что в сборке и pass-сертификате |
| `PC_ORGANIZATION` | Реальный издатель, видимый в карточке |
| `PC_CONTACT` | Ваш рабочий контакт, показываемый в подробностях |
| `PC_CERTIFICATE` | Абсолютный путь к pass-сертификату, PEM или DER |
| `PC_PRIVATE_KEY` | Абсолютный путь к его закрытому PEM-ключу |
| `PC_KEY_PASSWORD` | Пароль ключа; пусто только для незашифрованного ключа |
| `PC_WWDR_CERTIFICATE` | Промежуточный сертификат из цепочки |
| `PC_APPLE_ROOT_CERTIFICATE` | Официальный Apple root, подписавший промежуточный сертификат |

`.env` читается как **доверенный shell-файл**, поэтому не используйте конфигурацию, присланную неизвестным лицом. Пути к файлам с пробелами заключайте в кавычки. Секреты на сервере лучше хранить в менеджере секретов; `.env` — вариант для личной разработки.

```bash
bash scripts/run-signer.sh
```

Скрипт сначала проверит настройки, сертификат, ключ и срок действия. Если проверка не пройдёт, сервер не начнёт слушать порт. Не включайте `--reload`, дополнительные workers и отладочный вывод для личных данных.

### HTTPS — обязательно

По умолчанию сервис слушает только `127.0.0.1:8787`. Это удобно для тестирования и локального reverse proxy, **но не адрес для доступа с iPhone**: `localhost` телефона указывает на сам телефон.

Для iPhone используйте собственный HTTPS-домен с доверенной устройством цепочкой TLS и локальным reverse proxy, направляющим запросы на loopback-сервис. Другой вариант — прямой HTTPS: установите `PC_BIND` и пути `PC_TLS_CERTIFICATE` / `PC_TLS_PRIVATE_KEY`. Это **сертификат веб-сервера**, не pass-сертификат Apple. Небезопасный HTTP на внешнем интерфейсе скрипт отклоняет; клиент не отключает TLS-проверку и не принимает перенаправления.

Настройте у reverse proxy лимит тела 5 MiB, отсутствие записи тела и Authorization, отсутствие кэширования ответов. Для MVP оставьте один процесс сервиса. Не выставляйте сервис без защиты в интернет. В архиве ничего не развёртывается автоматически.

## 4. Подключить приложение и выпустить карточку

В PocketCard → Настройки укажите HTTPS-адрес **без пути**, имя оператора и личный токен. Они сохраняются в Keychain этой установки; ни токен, ни endpoint не зашиты в приложение.

Откройте сохранённую заполненную карточку → Предпросмотр и выпуск → проверьте список отправляемых данных → подтвердите передачу. После ответа сервиса появится системный экран добавления. **Отмена этого окна не считается установкой.** После редактирования выполните выпуск ещё раз: установленная карточка обновится с тем же serialNumber.

Сначала используйте только вымышленные значения и несекретное изображение. Сравните реальный Wallet с предпросмотром. Отдельно проверьте фото на классическом Generic и на устройстве, поддерживающем Poster Generic.

## 5. Проверки и диагностика

```bash
source .venv/bin/activate
bash scripts/test-all.sh
```

Для выбранного симулятора: `SIMULATOR_UDID=<UDID> bash scripts/test-ios.sh`. Скрипт по умолчанию сам выбирает доступный iPhone с iOS 17+. При отсутствии runtime установите его через Xcode Settings → Components.

| Симптом | Что проверить |
|---|---|
| Не найден `PocketCardCore` | Открыта полная распакованная структура, `Package.swift` на уровень выше `ios` |
| Ошибка provisioning | Реальные Team/Bundle ID, доступ Wallet для App ID, профиль и устройство |
| Выпуск отключён | `ios/Local.xcconfig`, `WALLET_ACCESS_ENABLED`, настройки сервиса в приложении |
| `401` / `403` сервиса | Личный токен соответствует `PC_TOKEN` |
| `503` | Все PC-переменные, соответствие ключа, UID/OU сертификата, цепочка и срок действия |
| `429` | Уже выполняется выпуск либо достигнут лимит 10 попыток в минуту |
| Ошибка HTTPS | Адрес без редиректа, имя в TLS-сертификате, доверенная цепочка, доступность с телефона |
| Статус Wallet недоступен | Настройки сборки, entitlement, Pass Type ID и доступ к библиотеке |

Не публикуйте логи с содержимым карточек, Authorization или приватными ключами. Для отчёта об ошибке используйте синтетическую карточку.

## 6. Закоммитить самостоятельно

Распакованный `pocketcard-ios` — корень будущего репозитория. Скопируйте его **содержимое**, включая `.github` и `.gitignore`, в свой checkout. Или инициализируйте репозиторий прямо в этой папке и добавьте существующий remote. Проверьте `git status` перед коммитом. Оригинальный архив не содержит `.git`, секретов или результатов сборки; создание и отправка коммита остаются на вашей стороне.
